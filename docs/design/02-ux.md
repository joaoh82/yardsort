# 02 — UX & flows

## Layout

```
┌───────────────┬──────────────────────────────────────────┬─────────────────────┐
│ PROJECTS    + │  [claude ●] [shell] [+]                   │ Files | Changes     │
│               │                                          │                     │
│ ▾ marvinapp + │  ┌────────────────────────────────────┐  │ ▾ src/              │
│    local      │  │                                    │  │    app.tsx      M   │
│    fix-auth ● │  │   live PTY — the harness TUI       │  │    auth.ts      A   │
│    new-api  ◌ │  │                                    │  │ ▸ docs/             │
│ ▾ yardsort +│  │                                    │  │─────────────────────│
│    local      │  └────────────────────────────────────┘  │  diff of selection  │
│               │                                          │                     │
│ ⚙ Settings    │  branch: ys/fix-auth  ·  base: main      │                     │
└───────────────┴──────────────────────────────────────────┴─────────────────────┘
      left                       center                             right
```

All three panels are resizable; left and right are collapsible (keyboard shortcuts). Panel sizes and
the last selected workspace persist across restarts.

## Left panel — projects & workspaces

A two-level tree:

- **Level 1 — project**: name, collapse chevron, `+` (new workspace), context menu
  (reveal in file manager, open in editor, remove from Yardsort — never deletes files).
- **Level 2 — entries**:
  - `local` — always present, always first. Points at the project's own checkout (repo root) on
    whatever branch is checked out there, labelled with that branch name. Cannot be deleted.
  - one row per **workspace**: name, status dot, context menu (rename, archive, delete…).

Status indicators (derived from PTY activity, never from parsing agent output):

| Dot          | Meaning                                                                         |
| ------------ | ------------------------------------------------------------------------------- |
| ● pulsing    | something in the workspace is printing right now                                |
| ● solid      | running, quiet for 3 s — probably waiting for you                               |
| ◎ ringed     | an agent finished a long stretch of work you have not looked at yet             |
| ○ grey       | nothing running (never started, exited, or not resumed since the app restarted) |
| ● red (tabs) | the process exited with an error                                                |

A workspace's menu offers **Rename** (the label only — folder and branch keep theirs, so running
agents and saved conversations are undisturbed), **Archive** (the folder goes; branch, commits and
session history stay; it moves to a collapsed "archived (n)" group and can be **restored** to the
same path), and **Delete**. A workspace whose folder vanished can be restored from its branch.
Archiving and deleting both refuse to destroy uncommitted work without a second, explicit
confirmation.

The bottom of the panel holds Settings, and is where future top-level features will go.

### Adding a project

`+` next to PROJECTS opens a small dialog with two choices:

1. **Open project** — native folder picker.
   - Folder is a git repo → add it.
   - Folder is _not_ a git repo → offer "Initialize git here" (required; worktrees need a repo).
   - Folder is a subdirectory of a repo → add the repo root, tell the user.
2. **Create project** — _name_ + _parent path_ (folder picker, remembers last used).
   Creates `<parent>/<name>`, runs `git init`, and makes an **initial empty commit** — a repo with
   no commits cannot have worktrees, so we never leave a project in that state.

## Center panel — the work

### Composer (before a workspace exists)

Clicking a project's `+` does **not** create anything yet. It shows a composer:

```
        New workspace in  marvinapp

  ┌──────────────────────────────────────────────┐
  │ What should the agent work on?               │
  │                                              │
  └──────────────────────────────────────────────┘
  [ Claude ▾ ]  [ opus ▾ ]  [ effort: high ▾ ]   from: main ▾      [ Start ⏎ ]
```

- **Harness** — from the enabled harnesses in settings.
- **Model** — free-text combo box with per-harness suggestions. Must accept arbitrary strings: model
  names change faster than we ship. "Default" means _omit the flag entirely_.
- **Effort** — options come from the harness definition; hidden if the harness has no effort arg.
- **Branch** — one picker, two groups: _New branch from…_ (defaults to the project's default branch)
  and _Open existing branch_, which lists branches not checked out anywhere and opens one as-is.
- Last-used harness/model/effort are remembered per project.

On **Start**:

1. Generate a workspace name (slug from the message, or a generated name; always renameable).
2. `git worktree add -b <prefix>/<slug> <worktree-path> <base>`.
3. Spawn the harness in a PTY with `cwd` = the worktree, delivering the message via the harness's
   prompt transport.
4. Sidebar gains the new row; center switches from composer to terminal.

If step 2 or 3 fails the composer stays up with the message intact and the error shown inline.
Nothing half-created is left behind.

An empty message is allowed: it starts the harness with no prompt.

### Terminal (once a workspace exists)

- Tabs across the top: the harness session(s), plus plain **shell** tabs opened in the same worktree
  (for running tests, dev servers, git by hand).
- A footer strip: branch, base branch, ahead/behind, worktree path (click to copy / reveal).
- When the harness exits the tab stays, showing scrollback under a bar offering **Resume** (same
  conversation, fresh process, replaces the dead tab), **Fork** (a copy that goes its own way, in
  a new tab) and **Close**. A running conversation can be forked from its tab's context menu.
- A workspace with nothing running lists its **previous sessions** — title, when, how it ended —
  each with Resume / Fork. After a restart nothing is started automatically; this list is the
  two-click way back into every conversation.
- Selecting `local` shows the same thing, rooted at the repo itself — a harness or shell on the
  project's real checkout, no worktree involved.

## Right panel — files & changes

Follows the selected workspace. Two tabs:

- **Changes** (default), in two groups: _Uncommitted_ — the working tree against `HEAD`, what the
  agent is doing right now — and _On this branch · vs `<base>`_ — `HEAD` against the point where
  the branch left its base, what the workspace has produced so far. Each file shows its kind
  (A / M / D / R / U / !) and lines added and removed.
- **Files**: the worktree's file tree, leaving out `.git` and whatever `.gitignore` excludes. Folders
  load when opened, so repository size does not matter.

Clicking a file opens it in the lower half of the panel: a unified diff for a change, a read-only
view for a file, both syntax-highlighted. **Expand** shows the same thing in a large overlay for
comfortable review; **Edit ↗** opens it in the user's editor (Settings → General; common editors
are tried when none is set). Binary and very large files are named as such, not rendered.

Everything updates live from a file watcher, including the open diff; a diff whose change
disappears (committed, reverted) closes.

Under the list sits the way out of the workspace: a commit message box that takes **everything**
uncommitted (no staging area — a partial commit nobody asked for is the worse surprise), a
**Push** once the branch is ahead of its remote, and **Open pull request**, which pushes first if
it must and writes its title from the commits the remote has not got. Reading stays read-only:
nothing here stages part of a change or discards one. The pull request's number and what CI made
of it then appear on the workspace's own row in the sidebar.

## Settings

- **Harnesses** — see [04-harnesses](04-harnesses.md). List on the left, form on the right:
  label, command, prompt args, resume args, fork args, prompt transport, enabled toggle,
  _Restore defaults_, _Test launch_. Users can add custom harnesses.
- **Workspaces** — worktree root directory, branch prefix, what "delete" does to the branch.
- **General** — editor command, theme, terminal font/size, shell for utility tabs.

## Keyboard (initial set)

**Mod** is ⌘ on macOS and **Ctrl+Shift** on Linux and Windows — the terminal-emulator convention
(Ctrl+Shift+C copies). Plain Ctrl+letter always belongs to the program in the terminal: Ctrl+B is
"back one character" in a shell and the tmux prefix, Ctrl+W deletes a word, Ctrl+T transposes. App
shortcuts never take those away. Shortcuts match the character the layout produces, not the
physical key, so they follow the key caps on Dvorak or AZERTY.

| Shortcut              | Action                                                          |
| --------------------- | --------------------------------------------------------------- |
| `Mod+B` / `Mod+Alt+B` | toggle left / right panel                                       |
| `Mod+T` / `Mod+W`     | new shell tab / close tab                                       |
| `Mod+C` / `Mod+V`     | copy selection / paste (bracketed when the program asks for it) |
| `Mod+1..9`            | _planned:_ jump to workspace                                    |

Links in terminal output open with Ctrl+click (⌘+click on macOS); a plain click belongs to the
program's mouse reporting.
